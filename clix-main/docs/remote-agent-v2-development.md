# V2 开发文档：规划与多智能体

状态：待开发。依赖 V1 的连接、认证、本地工具和请求状态管理已验收。

## 交付目标

用户在远程模式使用 `/plan` 和 `/team`。规划和多智能体协调在服务器进行，用户在本地终端审阅计划，各任务通过同一客户端操作本地项目。工具结果和任务输出按所属任务展示。

## 开发任务

1. **远程规划**：在服务器接入 `plan/Planner`、`plan/ExecutionPlan` 和 `agent/PlanExecuteAgent`；严格校验任务 ID、依赖和环。所有规划目标交模型处理，不用关键词跳过规划。规划请求不提供工具。
2. **本地计划审阅**：新增计划展示、展开、执行、取消和补充要求的事件；客户端接入 `PlanReviewInputParser`。Enter 执行、Ctrl+O 展开、Esc 取消、I 补充要求；断线或超时不默认执行。raw mode 和普通行输入都要验证。
3. **多智能体**：服务器接入 `AgentOrchestrator`、`SubAgent`、`TeamPlanParser`。规划结果严格校验；审阅只接受 JSON 布尔值 `approved: true`，审阅请求不提供工具。每个任务、worker 和工具请求有独立 ID。
4. **本地工具调度**：各任务共用 V1 客户端执行入口；仅允许列表里的只读工具并行，最多四个；有写入、命令或浏览器工具时按现有批次顺序执行。结果按原调用顺序返回。共享项目中的写操作按原规则串行，不能因网络并发绕过。
5. **策略和取消**：每个计划分支和 worker 使用独立策略副本；只有声明依赖的上游任务发现的网址可传到下游。取消的任务不算失败；重新规划次数、失败后跳过规则沿用现有实现，不能额外启动已跳过的任务。
6. **显示与审计**：输出带任务来源，本地界面显示状态和错误；记录本轮全部策略结果，包括被拒绝调用。断线时等待确认的计划不自动批准，有副作用工具按 V1 的状态不明规则处理。

## 测试与完成条件

- 图校验测试：空任务、重复 ID、缺失依赖和环均失败；不提供工具给规划和审阅请求。
- 模拟客户端测试：审阅按键、补充要求、取消、断线、工具串行和只读并发；确认结果与任务 ID 正确关联。
- 策略测试：独立分支不能使用其他分支发现的网址；有依赖时按规则传递。失败、取消、重新规划与跳过行为和本地模式一致。
- 回归：`ExecutionPlanTest`、`PlannerGraphValidationTest`、`PlanExecuteAgentTest`、`AgentOrchestratorTest` 和计划审阅输入相关测试；不运行评测。
- 人工验收：Windows 终端分别验证 raw mode 和普通行输入，以及并行任务的可读输出。

完成标志：远程 `/plan` 经用户审阅后执行本地项目任务；远程 `/team` 能协同处理任务并在失败或取消时清晰汇报结果。
