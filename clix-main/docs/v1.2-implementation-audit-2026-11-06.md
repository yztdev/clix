# V1.2 cancellation / continuity implementation follow-up

Scope: additions made against the uploaded project snapshot. The authoritative
`remote-agent-cancellation-session-continuity-development.md` is unchanged.

## Implemented in this patch

- The native C launcher sources remain as historical/deferred code, but are not part of the current local-only Windows installation path.
- `tools/install-clix-windows.ps1` now installs `clix.cmd`, `clix.jar`, and a bundled Java Runtime; it removes an old `clix.exe` so PATHEXT cannot select the stale native launcher.
- `tools/build-clix-runtime-windows.ps1` uses `jlink` on the build machine to prepare the bundled runtime. End users do not need JDK, Maven, CMake, GCC, or MSVC.
- `tools/verify-native-windows.ps1` retains its historical filename but verifies the current CMD-based local installation.
- Remote `remote`, `login`, and `serve --remote` entry points are disabled in `Main`; remote implementation classes remain dormant for a future release.
- `ProviderOutputGate`: serialized cancel/delivery and non-destructive digest
  snapshot; regression tests for both behaviors.

## Unverified / not complete

- The CMD + bundled Runtime installation and JNA `SetConsoleCtrlHandler` path still require real Windows validation. The C launcher is not required for the current release path.
- Provider Adapter first-boundary per-turn gate is **not fully wired** across
  concrete provider adapters. Server-level `RemoteAgentSession` gate remains in
  place but must not be counted as the required provider-level interception.
- Real keyboard first/second Ctrl+C and WSL cgroup/setsid, Job Object, DrvFS,
  crash/network-recovery acceptance criteria require Windows/WSL hosts.
- Maven and Windows build toolchain are not installed in this runtime; Java
  unit and full regression tests have **not been rerun** for this patch.

The project therefore **does not yet meet** the V1.2 all-criteria definition
of done. Do not label stage four or acceptance criteria 12/13 as complete.
