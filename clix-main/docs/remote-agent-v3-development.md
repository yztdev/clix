# V3 开发文档：MCP、Skill 与浏览器

状态：待开发。依赖 V1 和 V2；先完成工具执行位置和权限设计，再开放各类工具。

## 交付目标

远程 Agent 可按需使用本地 MCP 服务、项目 Skill 和本地浏览器。MCP 是扩展工具协议，Skill 是按需加载的任务说明；客户端执行这些需要本机环境的能力，服务器负责 Agent 对话和本轮策略。

## 开发任务

1. **本地 MCP**：客户端管理 `mcp/` 服务、工具注册、原始 JSON Schema 校验和子进程；服务器仅获得本会话允许使用的工具定义及结果。保留项目服务配置指纹信任、环境变量白名单、人工确认、退出与重启策略。首版仅接本地 stdio 服务；HTTP 断线重连、OAuth 和 sampling 不在本版范围。
2. **Skill**：客户端发现项目与用户 Skill，执行项目 Skill 信任检查，加载正文和附属文件；服务器收到必要内容后，按照现有规则注入对话。同轮注入、去重、字符上限、压缩时移除与重新加载规则不变。经验写回只由客户端的 `save_skill_reference` 写允许的补充目录。
3. **浏览器**：客户端连接和管理本地浏览器会话；公开页面默认使用隔离会话，切换到复用用户浏览器的模式需按现有规则确认。整批包含浏览器调用时串行执行，不把服务器浏览器误当作用户浏览器。
4. **网址来源策略**：服务器维护本轮原始网址和结构化搜索结果，执行已有 `TurnToolPolicy`；客户端也校验服务器附带的会话和调用权限。正文、工具结果或模型输出不能新增允许访问的网址；计划分支和 worker 的策略独立。
5. **权限与断线**：MCP 和敏感浏览器操作继续请求人工确认；断线后未确认操作不执行，已提交但结果未知的操作不自动重放。MCP 子进程及浏览器会话的关闭与恢复由客户端管理，并在界面显示状态。

## 测试与完成条件

- 用模拟 stdio 服务验证工具注册、原始 Schema、确认拒绝、子进程环境白名单、意外退出与受限重启。
- 验证未经信任的项目 Skill 不注入正文；加载、去重、压缩、重新加载和 `references` 写入均遵守现有规则。
- 用本地测试页面验证网址来源、敏感页面确认、浏览器批次串行、隔离和断线行为；不访问用户真实浏览器会话。
- 回归 `mcp/`、`skill/`、`browser/`、策略和相关 Agent 测试；不调用真实模型或评测。

完成标志：用户能在远程 Agent 中使用已信任的本地 MCP 和 Skill、经允许的本地浏览器，同时确认和网址限制与本地模式一致。
