# V4 开发文档：会话恢复、记忆与任务

状态：待开发。依赖 V1 的请求状态管理以及 V2、V3 的任务和工具事件。

## 交付目标

支持用户在客户端重连后查看并恢复可恢复的对话；项目记忆与长期记忆按用户和项目隔离；支持明确限定条件的后台任务与本地快照回滚。

## 开发任务

1. **会话记录**：服务器为每个用户和项目保存追加式会话记录；沿用 `ConversationLedger` 的恢复约定，直接修改实际对话历史后写 `view_checkpoint`。事件按序号回放，用户只能访问自己的记录。保留模型要求带回的 `reasoning_content`。
2. **恢复机制**：客户端发送会话标识和已收到的事件位置，服务器检查所属用户与项目。恢复已完成的对话视图；对于上次中断的工具请求，只有能可靠证明结果的才展示结果，状态不明时停止并提示用户，不重新执行。
3. **项目与记忆**：客户端提供项目根目录中的 `CLIX.md` 和本地项目标识；服务器按用户、客户端和项目隔离记忆，避免不同机器同名目录混淆。长期记忆继续加锁、去重和冲突检查；自动提取只取用户原话、遵守外部内容暂停规则。
4. **后台任务**：复用 `DurableTaskManager` 的任务状态，但首次交付只允许明确可在服务器独立完成的任务；任何需要本地文件工具或人工确认的任务必须等已认证客户端在线，掉线即暂停或结束并提示，不在服务器替代执行。任务重启不自动重放状态不明的本地操作。
5. **快照与回滚**：文件快照由本地 `SnapshotService` 管理，服务端只保存会话关联标识。回滚在客户端进行，继续执行原有检查和确认；断线或结果不明时不自动重复。
6. **保存与清理**：明确保存范围、期限、备份和删除方式；用户凭证及模型密钥不写入会话正文。对话可能包含项目代码，管理操作按用户隔离。

## 测试与完成条件

- 对话压缩、清理和恢复后，模型看到的历史与检查点一致；思考内容不丢失。
- 同名项目、不同用户和不同客户端的会话与记忆互不串用；记忆并发写入、重复和冲突按现有规则处理。
- 分别测试客户端离线、服务端重启、确认等待和结果不明；后台任务不会在无客户端时执行本地工具。
- 快照恢复拒绝越界及未授权操作；重复回滚请求不自动执行。
- 回归会话、上下文、记忆、任务、快照和安全相关测试；不执行评测或真实模型请求。

完成标志：用户重连后能查看并恢复可确认的会话；本地工具状态不明时能明确看到限制，记忆和任务不会跨用户或项目混用。
